# Transactional State Store

一个可执行的 C# 内存事务实验：对不可变字符串键值执行可重复读、乐观并发验证和原子批量提交。重点是解释为什么仅验证写集无法阻止写偏斜，以及如何通过缺失键版本和谓词验证覆盖 ABA 与幻读。

本项目于 **2026-10-30** 新建，由 AI 辅助实现，是独立技术演示，不是历史商业代码或生产数据库。尚未进行 Unity 集成验证。

## 运行

需要 .NET SDK 9.0，无第三方 NuGet 依赖。

```sh
dotnet run --project tests/TransactionalStore.Specs -c Release
dotnet run --project demo/TransactionalStore.Demo -c Release
```

演示模拟两位值班医生同时尝试离岗：两笔事务各自读到另一位在岗，第一笔提交成功，第二笔因为读集版本过期被拒绝，避免无人值班的写偏斜。

## 工程内容

| 机制 | 解决的问题 | 对应规格 |
| --- | --- | --- |
| 开始事务时复制不可变值与版本 | 重复读取不会混合不同提交的状态 | 快照、原子转账观察 |
| 提交时校验读集和写集 | 丢失更新、盲写冲突与写偏斜 | 32 个并发写者、400 次带重试增量 |
| 删除保留墓碑版本 | 缺失→插入→删除不能伪装成从未变化 | ABA、缺失键读取 |
| 扫描记录全局版本 | 插入或删除导致的幻读 | 前缀扫描、保守误冲突 |
| 单锁验证及发布 | 冲突事务不会部分提交 | 批量失败、并发转账 |

20 项可执行规格包括 1000 轮随机事务与独立 `Dictionary` 模型比较、终态重用、大小写语义和参数边界。测试是自包含控制台程序，任一失败返回非零退出码。

## 最小用法

```csharp
var store = new MemoryStore();
using var tx = store.Begin();
tx.Set("inventory/sword", "4");
var result = tx.TryCommit();
if (!result.Succeeded)
{
    // 新建事务，重新读取并重新计算业务操作；不要直接重用已终止事务。
}
```

每个事务由一个调用者独占；多个独立事务可并发。`TryCommit` 无论成功还是冲突都会结束事务。`Scan` 返回独立只读结果。键使用 `StringComparer.Ordinal`，空键不允许，空字符串值有效，`null` 专用于内部删除标记。

## 取舍和边界

- `Begin` 是 O(N) 的快照复制，目标是清楚表达并发正确性，没有做 MVCC 版本链或持久化页优化。
- 任何并发写入都会使已有扫描事务失败，即使键不匹配前缀；这是保守且可串行化的策略，会降低吞吐量。
- 墓碑不回收，因此频繁创建和删除唯一键会增加内存；回收需要追踪最旧活跃快照。
- 没有磁盘持久化、崩溃恢复、分布式复制、自动重试或公平性保证，也不承诺在资源耗尽后恢复运行。

完整提交时序和正确性论证见 [设计说明](docs/design.md)。
